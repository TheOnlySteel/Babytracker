# Sleep and NurseryPad — what is in this branch and how to roll it out

Status as of 2026-09-18. This branch carries the implementation of `docs/core2-integration-plan.md` (v2). The code started from a Codex implementation package; it was reviewed in four parts (database, poller, web app, firmware), and the findings were fixed here before anything was committed. The live Supabase project already runs migrations 0001–0003 with the household's real data; none of 0004–0006 has been applied, no Edge Function is deployed, no cron is scheduled and no pad has been paired. **Automatic sleep derivation is off by default and stays off until step 8 below.**

## What is here

- **Migrations 0004–0006**: the `sleep` entry type (its own migration), `source_key` and `via` on entries, a one-running-sleep index, `sleep_observations` / `sleep_status` / `cw_requests`, household timezone, fenced poll leases and rolling-window quota admission, devices with hashed keys, a private `device` schema for the op log and auth helper, and the `device_snapshot`, `device_sleep_today`, `device_op`, `pair_device`, `manage_device` and `monitor_settings` RPCs. Every function revokes execute from PUBLIC and grants only its intended role.
- **Edge Function `cradlewise-poll`**: scheduler-secret gate before any work, lease and admission through the database, the documented Cradlewise v1 shapes (`docs/cradlewise-data-api.md`), provisional live derivation and hourly c-chart reconciliation. Shared calendar code lives in `supabase/functions/_shared/sleep-time.ts` and the web app re-exports it.
- **Web app**: Sleep card with the crib chip and staleness, Sleep sheet (edit, timer, "log an earlier nap"), banners for breastfeed, pump and sleep, pump timer mode with real elapsed time and an unsplit `total_ml`, interval-overlap sleep totals with a Last night view, History under the household timezone, Settings sections for the monitor and paired devices, expanded exports, and an explicit fallback for entry types the app does not know.
- **NurseryPad firmware** under `NurseryPad/`, a fork of `CradleWatch/` that reads the snapshot RPC instead of Cradlewise. CI compiles it with the pinned toolchain. Its blockers (a use-after-free on every response, a queue that wedged on one refused log) are fixed; the screen layout does not yet match the design canvas and several CradleWatch niceties are missing. Its README lists what remains, and it should not replace the standalone monitor until that list and the hardware checks are done.
- **Tests**: 66 unit and PGlite database tests (`npm test`), the same database suite on native Postgres 16 in CI, six Playwright phone scenarios against a mocked Supabase (`npm run test:e2e`), Deno type check, Arduino compile.

## Changes made to the Codex version before commit

Database: the `via` backfill no longer bumps `updated_at` on 800 imported rows (trigger disabled around it); the poll lease token is hidden from caregivers by a column grant; malformed timestamps and out-of-range numbers in a device op return `invalid` instead of an HTTP 500; a null protocol is rejected; `sleep_dismiss` tolerates a missing `source`; a wet-and-dirty diaper reports `both`; longest nap is the nap's own length; a one-shot bottle or diaper from a pad whose clock has not synced is accepted at receipt time with `time_uncertain` instead of refused; `metrics_error` is separate from `source_error`.

Poller: query timestamps encode the space as `%20` as the documentation requires (Codex sent `+`, which 422s); parsers tolerate absent optional fields and unknown status values; the c-chart parser drops only the intervals it cannot trust (unknown labels, caregiver-added events, ambiguous DST times) instead of rejecting the whole batch, and reports what it dropped; a bad day-metrics payload or 4xx never pauses status polling; rate-limit pauses are capped at one hour; a wake shorter than one poll (visible only as a changed `since`) closes the old row; a wake confirmed before an outage beats the gap rule; the NAPS banner is parsed as nap intervals; an invalid household timezone falls back to UTC instead of throwing.

Web: the household timezone is unknown until the server says so and the device zone is used meanwhile (Codex hardcoded Los Angeles and regrouped existing days); our own day boundaries resolve leniently through DST gaps while vendor timestamps stay strict; the pump sheet's "Keep mine" re-saves the edit instead of discarding it; the breastfeed banner keeps its side and paused indicators, undo labels and reconnecting hint; cross-midnight sleeps appear once in History under the day they began; the 16-hour confirmation fires only when times changed; pump minutes are whole; totals show their amount; the monitor RPC no longer delays first paint; Prettier was removed as unused.

## Rollout, in order

1. Back up the database (Supabase dashboard → Database → Backups, or a `pg_dump`). Apply **0004, then 0005, then 0006** as three separate migrations with the Supabase connector's `apply_migration`, never pasted together: the enum value must commit before 0005 references it.
2. In the web app's Settings, confirm the household timezone (it defaults to America/Los_Angeles in the database) so History and Summary group days the way the phones already do.
3. Unplug or reflash **every** standalone CradleWatch unit before the server poller starts. The token's quota has one consumer.
4. Add Edge Function secrets `CW_TOKEN` (from the Cradlewise dashboard), `HOUSEHOLD_ID` (`acced28e-72c4-4189-b859-e1d5b74ae85a`) and `SCHEDULER_SECRET` (any long random string). Deploy `cradlewise-poll` with `verify_jwt=false` from `supabase/config.toml`; the scheduler secret is what authenticates the cron.
5. Store `cradlewise_poll_url` and `cradlewise_scheduler_secret` in Vault, confirm `pg_cron` accepts `'30 seconds'` on this project, then run `supabase/schedule.sql`. If sub-minute schedules are unavailable, schedule one 60-second job; never a second unleased poller.
6. Watch Settings → Sleep monitor for a few minutes: status, observation age and requests in the last 24 h should move; `source_error`, `metrics_error` and `history_error` should stay empty. The raw responses are kept in `sleep_observations.raw` and `sleep_status.day_metrics`; compare them with `docs/cradlewise-data-api.md` and adjust the parsers if anything differs.
7. Deploy the web app (merge to main; Netlify builds it). Close and reopen the PWA on both phones so no old bundle stays open.
8. Turn on automatic crib logging in Settings. Compare one full night and several naps with the Cradlewise app, including a pickup, a short false start and a network gap. Wall-clock sleep entries and Cradlewise's "awake in bed" are different measures and are shown side by side on purpose.
9. Pair a pad in Settings (the key is shown once). Copy `NurseryPad/secrets.example.h` to the ignored `secrets.h`, fill in Wi-Fi, the public anon key, the device key, the project URL and the POSIX `TZ_STRING`; compile with the pinned versions in `NurseryPad/README.md`.
10. On two physical units, verify TLS against the live chain, touch and mute responsiveness during a hung request, the stale and neutral lamp states, boot modes, revocation, queue recovery across power loss, the ninth-entry refusal, and timer conflicts against a phone and the other pad.

Rollback: switch automatic logging off in Settings (`sleep_status.derive_enabled`); unschedule `cradlewise-poll` to stop collection as well. Keep observations, tombstones and human corrections. Never roll the enum back or delete sleep rows to undo a UI release.

## Verified here and not verified here

Verified in this environment on the final tree: `svelte-check` 0 errors, 66 unit and PGlite tests passing (3 private Nara fixture tests included), 6 Playwright scenarios passing, production build. Not runnable here and left to CI or hardware: the native Postgres concurrency job, the Deno type check, the Arduino compile, and everything on a board. The parser tests are synthetic payloads in the documented shapes, not captured baby data.
